# Skin Care App 产品共创记录

> 用途：持续记录产品设计过程中涌现的想法、已确认决策、待决问题和分歧处理。  
> 性质：工作记录，不等同于最终 PRD 或视觉规范。  
> 更新原则：按产品逻辑归类维护；保留重要决策的日期与原因，不把讨论内容无序堆叠到文末。

## 一、当前产品共识

### 产品定位

面向痘肌用户的长期皮肤管理伴侣。产品通过标准化照片与极简生活记录，帮助用户看清皮肤变化，并在数据积累后发现可能与变化共同出现的生活因素。

产品不提供疾病诊断，不推荐药品，不把相关性描述成因果关系。

### 体验伦理

- 用户不是等待被系统评分的对象；
- 皮肤状态不等于用户的自律程度、努力程度或个人价值；
- 产品如实记录变化，但不使用羞耻、恐吓、失败暗示或焦虑驱动留存；
- 在用户因面部状态感到不自信时，产品应提供克制、真诚且不敷衍的支持；
- 情绪支持不能掩盖安全风险；需要就医提示时，仍应以平静、明确的方式表达。

### 核心价值闭环

```text
标准化记录皮肤状态
→ 快速记录当天生活因素
→ 观察一段时间内的皮肤变化
→ 提示反复共同出现的可能关联
→ 用户在后续记录中继续验证
```

趋势追踪和生活因素关联共同构成核心价值，不能把生活因素关联降级为可有可无的附加功能。

## 二、已确认决策

### D-001 — 首批核心用户

- 日期：2026-07-30
- 状态：已确认
- 决策：优先服务 18～30 岁、受轻中度反复长痘困扰，并愿意通过持续自拍了解皮肤变化的用户。
- 原因：与“长期追踪而非医疗诊断”的定位匹配，也适合验证 7～30 天持续记录行为。

### D-002 — 第一核心承诺采用“趋势 + 生活关联”

- 日期：2026-07-30
- 状态：已确认
- 决策：
  - 帮助用户看清皮肤是否真的在改善；
  - 帮助用户发现睡眠、压力、经期、饮食、新产品等因素与皮肤变化之间可能存在的个人关联。
- 原因：市场上已有大量单次 AI 测肤、照片对比和趋势产品，只提供趋势追踪容易同质化。个人生活因素关联是本项目的重要差异点和长期数据价值。
- 表达边界：只表达“共同出现”“可能相关”“值得继续观察”，不声称某个因素导致爆痘。

### D-003 — 日常记录必须低门槛

- 日期：2026-07-30
- 状态：已确认
- 决策：
  - 拍照后的日常记录采用常见选项快速点选；
  - 不要求用户填写长文本；
  - 默认交互应在很短时间内完成，并允许跳过不适用的项目；
  - 重点降低认知负担和操作负担，服务长期坚持，而不是追求单日数据尽可能完整。
- 原因：记录步骤过长或需要组织文字，会显著增加长期坚持的难度。

### D-004 — 生活因素选项采用插画化表达

- 日期：2026-07-30
- 状态：方向已确认，具体风格待视觉方案确认
- 决策：
  - 常见选项以图形为主要识别方式，文字仅作为必要的辅助标签和无障碍信息；
  - 倾向清新的卡通插画；
  - 可使用带白边的剪切画、贴纸或邮票式载体；
  - 食物类可出现奶制品、水果、火锅、甜品等直观物件；
  - 其他类别需要建立同一套可扩展的视觉语言，例如睡眠、压力、经期和新护肤品。
- 目标：让记录更轻松、有趣，并形成用户愿意反复完成的微型仪式。
- 约束：
  - 不能为了可爱牺牲选项辨识度；
  - 不能只依赖图像传达含义，需保留短标签、选中状态和读屏描述；
  - 避免低龄化、过度游戏化，以及淡化敏感健康数据的严肃性。

### D-005 — 现有 App 视觉稿作为品牌基线

- 日期：2026-07-30
- 状态：已确认沿用
- 参考：`design/prompts/UI/exec-39fc4f53-987f-4524-b151-3f2364a72a76.png`

  - 插画可以更有趣，但配色、字体层级和信息密度需与现有页面保持一致。

### D-006 — 产品设计不强依赖 Figma

- 日期：2026-07-30
- 状态：已确认
- 决策：
  - Figma 作为后续视觉比较、协作和交付工具，不作为产品规划的前置条件；

### D-007 — 采用“每日轻记录 + 每周标准记录”

- 日期：2026-07-30
- 状态：已确认
- 每日轻记录：
  - 拍摄一张正面快照；
  - 完成一次插画贴纸式生活因素记录；
  - 目标是在一分钟内完成，维持连续数据和使用习惯。
- 每周标准记录：
  - 完成正面、左侧和右侧三视角标准拍摄；
  - 用于生成更可信的阶段趋势与区域变化结果。
- 原因：
  - 每天三视角拍摄负担过高，容易损害长期留存；
  - 只做周记录又会损失生活因素和皮肤状态的连续性；
  - 双层节奏同时兼顾低门槛、趋势可信度和生活因素关联所需的数据密度。
- 待细化：每周标准记录的触发日、补拍规则、提醒频率，以及日常正面快照是否允许跳过。

### D-008 — 每日任务采用分级完成

- 日期：2026-07-30
- 状态：已确认
- 决策：
  - 完成正面快照或贴纸日记中的任意一项，都可以保存为当天记录；
  - 两项都完成时，标记为“完整记录”；
  - 不因用户当天无法完成全部任务而中断其记录路径。
- 数据表达：
  - 趋势和关联报告需要区分完整记录、仅照片、仅日记和未记录；
  - 缺失数据不能被系统当作“该因素没有发生”；
  - 当数据不足时，关联提示应降低置信度或暂不输出。
- 产品目的：允许低状态用户留下最小记录，减少“今天没做全，之后干脆不做”的放弃心理。

### D-009 — 日记采用“核心状态单选 + 生活事件贴纸多选”

- 日期：2026-07-30
- 状态：已确认
- 核心状态：
  - 睡眠、压力、经期等需要连续观察的维度采用快速单选；
  - 每个维度提供少量插画化状态，避免输入文字。
- 生活事件：
  - 饮食、新护肤品、运动等按是否发生进行贴纸多选；
  - 只让用户记录当天实际出现的事件，不逐项回答大量“是/否”问题。
- 缺失语义：
  - “没有发生”和“跳过未填”必须是不同状态；
  - 用户明确完成该类别且未选事件，才可解释为当天没有记录到该事件；
  - 跳过或未完成不能作为关联计算中的负样本。
- 体验目标：常规情况下约 20～30 秒完成，同时保留足以支持生活因素关联的数据质量。

### D-010 — 生活因素关联采用渐进式反馈

- 日期：2026-07-30
- 状态：已确认
- 第 1～6 天：
  - 不输出关联猜测；
  - 告知用户系统正在积累个人数据，并展示有效记录进度。
- 第 7 天：
  - 展示数据完整度和已覆盖的因素；
  - 只给出描述性观察，不形成因素结论。
- 第 14 天：
  - 数据满足最低条件时，出现低置信度的“可能共同出现”提示；
  - 数据不足时明确说明还缺少什么记录。
- 第 30 天：
  - 生成第一份个人生活因素关联报告；
  - 报告同时展示样本量、数据完整度和置信程度。
- 后续：
  - 随新增数据持续更新；
  - 允许旧观察被减弱、推翻或替换，不把早期结果固化成用户标签。
- 原因：兼顾早期留存反馈和结论可信度，避免用少量数据制造虚假的个人规律。

### D-011 — 产品中禁止皮肤评分和评级

- 日期：2026-07-30
- 状态：已确认，产品红线
- 发起背景：用户本人长期受痤疮困扰，也是产品的第一位目标用户，明确反对将面部状态转化为分数或等级。
- 禁止内容：
  - 不展示皮肤综合分、健康分、颜值分或类似指标；
  - 不使用“优秀、良好、较差、糟糕”等评级；
  - 不用红色跌幅、扣分、排名、输赢或失败感表达皮肤波动；
  - 不通过“今天下降了多少分”制造焦虑和回访压力；
  - 不把连续打卡包装成对用户自律和价值的评价。
- 允许内容：
  - 克制描述可见外观状态；
  - 比较不同时间记录中的具体变化，并同时表达不确定性；
  - 说明“皮肤会自然波动，单次变化不代表你做错了什么”；
  - 在必要时提供平静、明确的专业就医提示。
- 数据边界：
  - 后端可以保留支持算法、趋势计算和安全规则所需的结构化特征；
  - 结构化特征不能在前端重新包装成面向用户的综合分数或等级；
  - 是否向用户显示具体数量仍需单独决策，默认不以数量制造压力。

### D-012 — 每日反馈采用“观察 + 陪伴”，不采用评价

- 日期：2026-07-30
- 状态：方向已确认，具体文案待设计
- 推荐结构：
  1. 确认记录已被妥善保存；
  2. 使用中性语言描述相较上次记录的可见变化；
  3. 提醒单日波动和拍摄条件带来的不确定性；
  4. 给出不带指责的陪伴性回应；
  5. 需要时单独显示安全提示。
- 陪伴文案原则：
  - 不强行乐观，不说空泛鸡汤；
  - 不把皮肤状态与美丑、努力、自律或个人价值绑定；
  - 不使用“坚持就一定会好”等无法保证的承诺；
  - 根据真实记录回应，不重复机械安慰；
  - 让用户拥有选择权，例如“今天只记录到这里也可以”。

### D-013 — LLM 结果必须执行情绪安全约束

- 日期：2026-07-30
- 状态：原则已确认，Prompt 与输出审计规则待设计
- 输出建议拆分为结构化字段：
  - `neutral_observations`：中性外观观察；
  - `comparison_context`：与历史记录的克制比较和不确定性；
  - `supportive_message`：与当前情境匹配的支持性回应；
  - `safety_notice`：仅在触发规则时出现的就医提示；
  - `prohibited_claims` 或审计标记：供后端合规扫描。
- Prompt 硬约束：
  - 禁止输出任何评分、评级、排名和价值判断；
  - 禁止将皮肤波动归咎于用户；
  - 禁止诊断、病因断言和药品推荐；
  - 禁止夸大变化、灾难化表达或制造紧迫焦虑；
  - 观察必须带有图像条件和模型不确定性意识；
  - 支持性回应不能覆盖或弱化必要的安全提醒。
- 不能只依赖 Prompt，需采用四层防线：
  1. 生成 Prompt 明确语气、禁区和合格示例；
  2. JSON Schema 将观察、陪伴和安全提示拆开，限制模型自由发挥范围；
  3. 后端执行确定性的评分/评级词、归责表达、诊断词和灾难化语言扫描，违规时重写或降级为安全模板；
  4. 建立覆盖状态稳定、明显波动、严重状态和低质量照片的情绪安全回归集，持续检查输出。

### D-014 — 默认不展示数量，详细数据由用户主动展开

- 日期：2026-07-30
- 状态：已确认
- 默认体验：
  - 只展示克制的状态观察、历史照片对比和必要的不确定性说明；
  - 不在首页和每日结果中突出痘痘数量、变化百分比或其他数字。
- 详细记录：
  - 用户主动点击“查看详细记录”后，才显示区域数量、类型记录和变化数据；
  - 详细页仍禁止综合分数、等级、价值判断和红绿输赢式表达；
  - 用户应能随时退出详细视图，产品不通过弹窗或提醒强迫其查看。
- 原因：既保留长期证据和可验证数据，又不强迫所有用户每天面对可能放大焦虑的数字。

### D-015 — 产品采用“能力底座—产品定位—交互呈现”三层模型

- 日期：2026-07-30
- 状态：已确认
- 第一层：可信记录与证据能力
  - 标准化拍摄、每日轻记录、每周三视角、贴纸日记、历史对比、趋势和生活因素关联；
  - 是产品成立的事实基础，也是情绪陪伴和个性化 Agent 不胡说的前提。
- 第二层：温柔的皮肤陪伴者
  - 是整体产品定位，不是一个独立功能；
  - 无评分、无羞耻、无焦虑驱动、诚实描述不确定性和尊重用户选择，需要贯彻首页、拍摄、日记、报告、提醒和对话。
- 第三层：面向消费者的交互呈现
  - 对话式个人 Skin Agent 是重要呈现方式之一；
  - Agent 基于第一层数据提供动态追问、解释、陪伴和后续提醒；
  - 产品仍保留结构化操作界面，不能把高频拍摄、贴纸选择和报告浏览全部改成低效率的对话。
- 演进关系：
  - MVP 同时建立第一层和第二层；
  - 第三层先提供克制的问答与情境化回应；
  - 随个人数据积累，再增强主动追问、个性化记忆和关联解释。

### D-016 — AI 采用“隐形能力”模式，不提供自由问答入口

- 日期：2026-07-30
- 状态：已确认，修正 D-015 中独立对话入口的设想
- 产品原则：
  - App 不设置独立的“问答”“陪伴”或通用聊天入口；
  - 不向用户暴露可自由输入任意问题的多轮对话框；
  - 用户感受到的是个性化观察、恰当追问和温和回应，而不是在使用一个套壳通用大模型。
- 原因：
  - 自由问答会使 LLM 调用次数和 Token 成本难以控制；
  - 用户可能提出脱离皮肤长期管理定位的问题；
  - 通用聊天会稀释产品差异，使产品被理解为豆包、千问等通用助手的替代入口；
  - 多轮对话不是拍照、日记和长期趋势等高频任务的最高效交互。
- 推荐的固定 AI Function：
  - `generate_daily_observation`：根据当日记录和历史数据生成克制观察与支持性回应；
  - `generate_weekly_summary`：根据每周标准记录生成阶段总结；
  - `generate_correlation_observation`：数据达到门槛后生成生活因素共同出现的初步观察；
  - `select_contextual_follow_up`：只在确有必要时选择一个结构化追问，用户通过固定选项回答；
  - `explain_change_context`：解释某项变化为何仍需继续观察，避免用户把单日波动理解成失败；
  - `compose_supportive_copy`：在严格语气边界内生成与当前情境匹配的陪伴文案。
- 交互约束：
  - AI 追问最多一次一个问题；
  - 优先使用插画选项、单选或多选，不要求用户自由输入；
  - 每个 Function 使用固定输入字段、固定输出 Schema 和明确的触发条件；
  - 不允许 Function 访问与当前产品任务无关的开放式问题。
- 成本控制：
  - 调用由完成记录、生成周报、达到关联门槛等明确事件触发；
  - 结果幂等缓存，同一数据版本不重复调用；
  - 无变化时优先使用安全模板，不强制调用 LLM；
  - 按 Function 设置独立模型、Token 上限、每日额度和降级策略；
  - 模型供应商保持可替换，不在产品层绑定某一家通用聊天品牌。

### D-017 — 一级导航采用“今天 / 历程 / 我的”

- 日期：2026-07-30
- 状态：已确认
- 今天：
  - 每日正面快照、贴纸日记和每周标准拍摄的统一任务入口；
  - 在记录完成后承载克制的当日观察和情境化支持。
- 历程：
  - 承载日历、历史照片、前后对比、阶段趋势、周报和生活因素关联；
  - 默认无评分、无评级，详细数字由用户主动展开。
- 我的：
  - 承载提醒偏好、隐私授权、数据导出/删除、详细数据展示偏好和账号设置。
- 明确不设置：
  - 不设置独立“问答”“陪伴”或通用 AI 入口；
  - AI 输出嵌入上述固定业务页面和固定组件中。

### D-018 — 原始皮肤照片不可被生成式修改

- 日期：2026-07-30
- 状态：已确认的产品红线。
- 用户上传或拍摄的皮肤照片必须作为真实记录保存，禁止：
  - 美颜、磨皮、祛痘、增删皮损；
  - 生成式扩图、重绘、风格化或卡通化；
  - 以 AI 生成内容替换原始照片的任何区域；
  - 为了配合 App 视觉风格而改变照片中的真实皮肤表现。
- 原始文件与展示方式必须分离：
  - 原始文件保持不可变，不允许处理结果覆盖原图；
  - 页面裁切应优先采用视口裁切，不生成新的用户照片；
  - 隐私遮挡应优先采用独立 UI 覆盖层，不把模糊效果写回原图；
  - 如因安全需要移除 EXIF、修正方向或生成传输缩略图，必须被定义为透明、可审计的技术处理，不得改变皮肤像素语义，也不得冒充原图。
- AI 只能输出结构化观察或文字，不得向用户返回经过生成、修复或润色的脸部照片。

### D-019 — 每周标准拍摄替代当天日常快照

- 日期：2026-07-30
- 状态：已确认。
- 普通日期的照片任务是“留一张今天的正面快照”。
- 每周标准拍摄日，同一任务自然展开为“完成本周标准记录”，包含正面、左侧、右侧三张照片。
- 完成每周标准拍摄后，自动计入当天的照片记录，不再要求用户额外拍摄一次正面快照。
- 贴纸日记始终是与照片任务并列的独立入口，可以单独完成。
- 设计目的：维持日常记录的低门槛，避免周拍日产生重复任务，同时为周期对比保留更完整的数据。

### D-020 — 记录后即时回应，但 AI 不必每次说话

- 日期：2026-07-30
- 状态：已确认。
- 用户保存照片或贴纸日记后，立即显示确定、温和的系统反馈，例如“今天的记录已收好”。
- 若另一项记录尚未完成，可以邀请用户继续补充，同时明确“不补也没关系”，不制造任务压力。
- 只有在数据充分且确实出现值得表达的新信息时，才展示“今天的小观察”。
- 没有新信息时保持安静，不生成空泛、重复或为了体现 AI 存在感而出现的分析。
- 该策略同时服务于：
  - 避免用户感觉每次记录后都在接受皮肤检查；
  - 控制 LLM 调用频率和成本；
  - 提升少量 AI 输出的可信度与信息价值。

### D-021 — “今天”页采用逐渐丰富的单页手账

- 日期：2026-07-30
- 状态：已确认。
- 不把照片记录和贴纸日记设计成两张待办任务卡，也不使用复选框或任务进度条。
- 页面主体是一张“今日手账页”：
  - 照片入口表现为手账中的相纸位置；
  - 生活记录入口表现为等待贴入内容的贴纸区域；
  - 点击相应区域进入拍摄或生活记录流程。
- 用户完成记录后，对应内容自然出现在手账页中，使页面从留白逐渐变得丰富。
- 体验目标是“慢慢留下今天”和轻微收藏感，而不是“完成两项任务”。
- 照片在相纸区域中的默认可见方式仍沿用 I-006 的候选方案，本决策不提前锁定照片遮盖方式。

### D-022 — “今天”页采用手账优先的信息层级

- 日期：2026-07-30
- 状态：已确认。
- 页面从上到下依次为：
  1. 自然问候、日期和一句轻量引导；
  2. 作为视觉中心的今日手账页；
  3. 以便签形式出现的即时记录反馈；
  4. 仅在确有新信息时出现的“今天的小观察”；
  5. “今天 / 历程 / 我的”底部导航。
- 今日手账页包含日期小标签、相纸区域和生活贴纸区域；周拍日相纸区域展开为三张叠放相纸。
- 页面不展示连续记录天数、完成百分比、任务进度条或皮肤结果评分。
- 打开页面时，用户首先感受到的是“今天留下了什么”，而不是“还有什么没完成”或“皮肤结果如何”。

### D-023 — “历程”页以近期篇章作为封面

- 日期：2026-07-30
- 状态：已确认。
- 打开“历程”时不直接进入月历，也不直接展示趋势仪表盘。
- 页面顶部首先展示一张“这一周”手账式篇章卡，组合：
  - 本周照片回看入口；
  - 本周出现过的代表性生活贴纸；
  - 一句克制、中性的阶段观察。
- 用户先感受到“这段时间留下了什么”，再主动进入月历、照片对比和生活关联等更深层内容。
- 该结构兼顾生活手账的亲近感与趋势、关联洞察的产品价值，同时避免呈现为医疗报告或数据分析后台。
- 篇章卡不包含评分、评级、红黄绿状态或结论性诊断。

### D-024 — “历程”页设置三个书签式二级入口

- 日期：2026-07-30
- 状态：已确认。
- “这一周”篇章卡下方设置：
  - “翻看日历”：按日期回看每日手账，不显示断签、补签或缺失惩罚；
  - “照片对照”：由用户选择两个日期或两组标准周拍进行原图对照，不生成评分；
  - “生活线索”：展示生活记录与皮肤变化之间逐渐积累的共同出现现象，明确不等同于因果结论。
- 历史内容通过“继续往前翻”按周排列篇章卡，不以无限趋势图作为主浏览方式。
- 产品措辞使用“翻看 / 对照 / 线索”，避免“趋势分析 / 影响因素 / 诊断报告”等带有检查感或确定性的表达。

### D-025 — 生活线索采用达到门槛后的渐进提醒

- 日期：2026-07-30
- 状态：已确认。
- “这一周”篇章封面平时只做阶段回顾，不直接铺开展示弱关联。
- 只有当线索达到最低数据量和可信条件时，篇章封面才出现一枚轻量书签，例如“发现一条值得继续留意的生活线索”。
- 用户主动点击书签后，才进入详细线索页查看：
  - 共同出现的生活记录与皮肤变化；
  - 所依据的记录范围；
  - 明确的“不代表因果”说明。
- 证据不足时保持安静，不展示弱线索，也不使用“还差几天解锁”等机制催促用户记录。
- 设计目的：让 AI 在适当时机提供价值，同时避免把不确定现象表达为结论或制造记录压力。

### D-026 — 用户可以用一键反馈纠正生活线索

- 日期：2026-07-30
- 状态：已确认。
- 生活线索详情提供两个轻量操作：
  - “继续留意”；
  - “这条不太符合我”。
- 该交互不是要求用户评价 AI，而是把对自身身体和生活情境的解释权保留给用户。
- 选择“这条不太符合我”后：
  - 不删除或篡改原始照片、日记和结构化记录；
  - 降低该线索及相似线索的展示优先级；
  - 后续有新数据时可以重新计算，但不得反复强推同一结论。
- 首版不提供开放文本解释框，避免增加记录负担，也避免形成通用问答入口。

### D-027 — 照片对照由系统推荐、用户主动揭开

- 日期：2026-07-30
- 状态：已确认。
- 系统可以根据拍摄角度、间隔和记录完整度，推荐两组适合对照的标准记录。
- 进入“照片对照”后，默认只显示日期与相纸封面，不立即展开两张真实照片。
- 用户主动点击“开始对照”后才展示原图，并且可以在展开前更换任一日期。
- 对照工具仅提供并排查看、滑动重叠和角度切换，不自动弹出“变好 / 变差”结论。
- 系统负责降低选择成本，照片是否揭开、比较哪些日期以及何时停止查看，始终由用户控制。

### D-028 — “我的”页采用温和封面与清晰设置并存

- 日期：2026-07-30
- 状态：已确认。
- 顶部使用简单的昵称、插画头像和个人化引导，不默认使用真实脸部照片作为头像。
- 页面主体按功能分为：
  - “我的记录方式”：提醒时间、每周标准拍摄日、常用贴纸类别；
  - “照片与隐私”：照片预览方式、应用锁、AI 分析授权、照片存储与删除；
  - “数据与账号”：记录导出、数据删除、账号与安全；
  - “关于与支持”：产品能力边界、隐私说明、反馈渠道和必要的就医提示。
- 页面可以延续手账封面感，但授权、删除、安全等高风险操作必须采用清晰、克制、符合标准交互预期的界面。
- 设计目标是在保持品牌温度的同时，让用户能够快速理解并控制自己的数据。

### D-029 — 隐私授权暂采用低调但及时告知的折中方案

- 日期：2026-07-30
- 状态：暂定，后续仍需结合技术数据流和合规评审确认。
- 首次启动采用市场常见、克制的隐私弹窗，提供完整隐私政策入口，不使用警报式视觉。
- 首次真正启用照片分析时，再以一屏简短说明告知：
  - 处理什么数据；
  - 用于什么目的；
  - 在哪里处理或由哪类服务方处理。
- 用户可选择“同意并继续”或“仅保存照片”；选择后者仍可拍照、记录贴纸和回看历史。
- “我的”页只展示简洁权限摘要，完整分项控制收进二级页面。
- 不采用默认勾选、故意难读、强制滚动到底或把非必要分析授权与基础记录功能捆绑的方式。
- 该方案是 C-006 的阶段性折中：界面保持低存在感，但实际数据处理不作模糊或误导性表达。

### D-030 — 提醒由用户选择并保持固定、克制

- 日期：2026-07-30
- 状态：已确认。
- 首次使用时邀请用户自行决定是否开启提醒，并选择适合自己的固定时间。
- 不根据用户行为自动推断或频繁调整提醒时间，避免产生被监控感。
- 每天最多发送一次记录提醒；每周标准拍摄日以周拍提醒替代普通日常提醒，不重复通知。
- 通知文案使用邀请式表达，例如“如果愿意，给今天留一点记录”，禁止使用“尚未完成、断签、坚持失败”等压力语言。
- 用户连续忽略多次后，系统自动安静暂停提醒，只在 App 内保留重新开启入口，不继续追发通知。

### D-031 — 首次使用采用渐进式引导

- 日期：2026-07-30
- 状态：已确认。
- 不在进入产品前要求用户填写完整的皮肤情况、生活习惯和隐私授权长问卷。
- 首次体验流程：
  1. 用一屏说明产品承诺：帮助记录变化、寻找生活线索，不评分、不诊断；
  2. 询问用户是否需要记录提醒，可以直接跳过；
  3. 进入空白的“今日手账页”，通过相纸与贴纸空位自然引导第一次记录。
- 相机权限只在用户首次点击拍照时申请。
- 照片分析授权只在用户首次真正启用对应功能时出现，遵循 D-029。
- 其他个人背景信息仅在后续确有数据需要时，以固定选项渐进询问，不形成长问卷或开放问答。

### D-032 — 禁止使用锁定、解锁和倒计时包装数据积累

- 日期：2026-07-30
- 状态：已确认。
- 不展示被锁住的报告、锁形图标、“还差 X 天解锁”、付费式遮罩或不可点击的洞察卡。
- 原因：
  - 容易让用户误以为需要付费才能查看自己的记录；
  - 会把正常的数据积累包装成人为限制；
  - 容易产生劝退感，并与温和、可信的产品定位冲突。
- 数据不足时只展示当前真实存在的记录内容，不伪造报告，也不预先摆出不可用功能。
- 二级入口应随真实能力自然出现：
  - 有记录后即可翻看日历；
  - 有两组适合比较的记录后再出现照片对照；
  - 真正形成可信线索后再出现生活线索书签。
- 新能力出现时采用页面自然生长的方式，不使用“恭喜解锁”等游戏化话术。

### D-033 — 长期能力从第一天提供可进入的成长预览

- 日期：2026-07-30
- 状态：已确认，是对 D-032“完全不展示未形成能力”部分的修正与补充。
- “照片对照”和“生活线索”入口从第一天即可看到并进入，提前解释产品的长期价值。
- 数据不足时不显示锁、灰色禁用态、倒计时或空白报告，而展示：
  - 非真实人脸的照片对照交互示例；
  - 生活贴纸与皮肤变化共同出现的说明性示例；
  - 清晰标注的“示例”，避免与用户个人结论混淆。
- 文案强调内容会随着真实记录逐渐形成，不使用“坚持 X 天解锁”，也不暗示付费。
- 当数据达到使用条件时，同一位置自然从示例说明替换为用户自己的照片对照或生活线索。
- 不承诺一定产生关联，只说明产品会尝试整理值得继续留意的共同出现现象。

### D-034 — 贴纸日记采用分类优先的组织方式

- 日期：2026-07-30
- 状态：已确认。
- 打开贴纸日记后，先展示稳定的生活因素分类，再进入该分类下的具体插画贴纸。
- 不采用“最近使用 / 常用贴纸”作为第一页的主要结构，避免随着选项扩展变得无序。
- 分类入口使用插画或邮票式封面配合短标签，兼顾活泼视觉、快速识别与无障碍理解。
- 进入分类后只展示少量常见选项，具体贴纸仍以插画为视觉主体，不使用长文字列表。
- 用户不需要逐个打开所有分类；可以选择任意一项后保存，也可以继续进入其他分类补充。
- 通过浅层返回、选中状态保留和固定保存入口，控制分类带来的额外操作成本。

### D-035 — 首版生活贴纸暂采用六个稳定分类

- 日期：2026-07-30
- 状态：方向基本确认，具体贴纸名称和数量仍需通过原型及用户测试调整。
- 首版一级分类：
  1. “吃喝”：奶制品、水果、火锅辛辣、甜品、高油食物、酒精等；
  2. “睡眠”：早睡、晚睡、睡眠充足、夜间醒来等；
  3. “心情与压力”：放松、忙碌、紧张、压力较大等；
  4. “护理变化”：使用新品、化妆、防晒、敷面膜、停用产品等；
  5. “生理周期”：经期前、经期中、经期后，可依据用户情况隐藏整个分类；
  6. “活动与环境”：运动出汗、长时间戴口罩、日晒、旅行换环境等。
- 分类封面以插画为主、短标签为辅。
- 每个分类首版控制在 4–8 个高频贴纸，后续新增具体选项时尽量保持一级分类稳定。

### D-036 — 贴纸日记采用“状态单选、事件多选”

- 日期：2026-07-30
- 状态：已确认。
- 单选分类：
  - 睡眠；
  - 心情与压力；
  - 生理周期。
- 多选分类：
  - 吃喝；
  - 护理变化；
  - 活动与环境。
- 用户可以只记录一个分类后直接保存，不要求六类全部填写。
- 分类封面可显示已选择贴纸的小缩影，帮助用户确认内容，但不显示“已完成 1/6”等进度表达。
- 该规则用于区分一天的主要状态与可能同时发生的多个生活事件，兼顾数据含义和记录效率。

### D-037 — 明确没有发生与未记录必须分开

- 日期：2026-07-30
- 状态：已确认。
- 未选择某个分类不能自动解释为“今天没有发生相关状态或事件”。
- 用户进入某个分类后，可以主动选择“今天没有特别的”，此时才记录为该分类的明确无事件状态。
- 用户没有进入的分类保持“未知 / 未记录”，后台不得将其作为阴性样本参与关联判断。
- 用户仍可只填写一个或少数分类后保存，不需要逐项确认六个分类。
- “未知”只用于内部数据语义与可信度判断，不在界面上显示为缺失，也不催促用户补齐。

## 三、正在探索的产品想法

### I-001 — 将习惯记录设计成手账体验

- 来源：用户提出
- 当前判断：值得作为重点视觉方向探索。
- 潜在价值：
  - 将机械打卡转化为“完成今天一页”的收集感；
  - 插画贴纸、日期、连续记录痕迹和月度页面天然适合表达生活因素；
  - 长期积累后，用户看到的不只是数据表，而是自己的皮肤与生活档案。
- 主要风险：
  - 整个 App 都采用强手账风，可能削弱 AI 分析和趋势结论的可信度；
  - 装饰过多会增加操作负担；
  - 视觉元素过密时，不利于快速点选和无障碍使用。
- 当前建议：
  - 日记填写、日历回顾和连续记录反馈可以采用明显的手账语言；
  - 分析结果、趋势图和隐私/就医信息保持清晰、克制和可信；
  - 用统一色彩、圆角、纸张纹理或轻量贴纸把两种语气连接起来，不把 App 做成纯工具，也不做成纯装饰手账。

### I-002 — “贴上今天的生活贴纸”交互隐喻

- 用户不是在填写一张表单，而是在当天页面贴上符合实际情况的生活贴纸。
- 点击选项后，插画可出现轻微“贴入”动效、白边阴影或盖章反馈。
- 当天记录完成后形成一张可回看的日记卡片。
- 该想法尚未确认，需结合操作效率、视觉方案和动效成本评估。

### I-003 — 三种手账视觉强度对比

- 方向 A：轻手账贴纸。保留现有卡片式布局，在生活选项上加入白边插画贴纸，变化最克制。
- 方向 B：邮票收藏册。选项以邮票格或小型收藏卡呈现，强化每天收集一页的仪式感。
- 方向 C：拼贴手账页。采用纸张、胶带、错落贴纸等更强的手账语言，情绪价值最高，但需重点控制信息密度与低龄感。
- 当前状态：待通过视觉草案比较后选择，也可以组合不同方向的优点。

### I-004 — 三种整体产品体验路线

- 路线 A：证据型皮肤档案
  - 以标准化记录、照片对比、数据完整度和克制趋势为核心；
  - 优点是可信、合规、MVP 边界清楚；
  - 风险是情绪支持较弱，容易仍被理解为普通追踪工具。
- 路线 B：温柔的皮肤陪伴者
  - 在可信记录基础上，加入非评判性反馈、手账式生活记录和适度情绪支持；
  - 不以分数、连续天数压力或焦虑驱动留存；
  - 优点是兼顾证据与陪伴，更贴合用户本人长期受痤疮困扰的真实体验；
  - 风险是 Prompt、文案与情绪安全机制需要投入更多设计和测试。
- 路线 C：对话式个人 Skin Agent
  - 以 AI 对话、动态追问和主动提醒为主要入口；
  - 优点是个性化强，长期数据积累后潜在壁垒高；
  - 风险是首版交互不稳定、成本较高，也更容易出现越界建议或伤害性表达。
- 状态：初始比较方式已被三层模型替代，保留本段用于追溯讨论过程；最终结论见 D-015。

### I-005 — “今天”页候选结构

- 顶部只展示日期、问候和非评判性引导语，不出现皮肤评分、评级或好坏标签。
- 主体是一张“今天的记录”卡片，包含两个可独立完成的入口：
  - 留一张今天的正面快照；
  - 贴上今天的生活贴纸。
- 任一入口完成即可形成一条有效记录；两项都完成时信息更完整，但不使用“未达标”“失败”等表达。
- 每周标准拍摄日，以正面、左侧、右侧三视角任务替代当天的单张正面快照，不额外增加重复任务。
- 保存后反馈“今天的记录已收好”，并以“想补充的话还可以……”提示未完成项，同时明确“不补也可以”。
- 数据足够时出现一张克制的“今天的观察”卡片，由固定 AI 功能生成中性观察和支持性文案；默认不展示数值，可由用户主动展开“查看详细记录”。
- 可描述“本周留下了几天记录”，但不设计断签、补签、连续打卡压力或红色警示。
- 页面底部使用“今天 / 历程 / 我的”三入口导航。
- 状态：待用户确认后转为页面设计决策。

### I-006 — 真实痤疮照片与轻松品牌视觉的共存

- 来源：用户提出。
- 核心矛盾：
  - 产品希望活泼、可爱、清新，避免医院、药品、医美和任务式打卡的沉重感；
  - 每日上传的痤疮照片是真实、私密且可能令用户不愿直视的内容，直接大面积展示会与整体视觉氛围冲突，也可能放大羞耻和焦虑。
- 需要解决的并非“让照片变好看”，而是：
  - 保留照片作为长期变化证据的真实性；
  - 控制照片在页面中的视觉权重和暴露程度；
  - 让用户决定何时、以何种方式查看；
  - 避免滤镜、美化或装饰干扰标准化比较；
  - 用轻松的容器与交互包裹真实内容，而不把痤疮本身卡通化或娱乐化。
- 候选设计原则：
  1. 不给记录照片添加美颜、柔肤、调色或卡通滤镜，避免破坏长期对比的可信度。
  2. 不在首页、日历等日常页面大面积直接展示正脸照片，避免用户每次打开 App 都被迫审视皮肤。
  3. 可使用相纸、硫酸纸、信封、拍立得背面等轻遮盖容器降低视觉冲击，由用户主动触发展示原图。
  4. 照片对比页采用温暖但克制的“观察空间”，减少贴纸装饰和视觉噪声，同时避免医院、药品、医美或器械感。
- 候选双层视觉模型：
  - 外层是轻松的生活手账，承载贴纸、日期、纸张和柔和植物色；
  - 内层是真实的个人档案，承载原始照片、标准角度和历史对比；
  - 可爱和轻松用于支持“记录自己”的行为，不用于美化、戏谑或卡通化痤疮本身。
- 默认照片呈现方式的未决候选：
  - 半透明硫酸纸轻遮盖，点击后揭开；
  - 展示较小的真实缩略图，点击后放大；
  - 收入“今日照片”信封，只展示已记录状态。
- 待探索：照片容器、默认预览方式、隐私遮罩、回看触发、对比页面和拍摄完成后的反馈语言。
- 状态：仅作为 idea 记录，暂不要求用户决策。

### I-007 — 主题色需要重新探索

- 来源：用户提出。
- 现有暖白与鼠尾草绿来自早期视觉草案，只能作为候选参考，不是已经确认的品牌色。
- 在开始任何页面、贴纸或手账视觉设计前，应先共同确定：
  - 产品希望传递的第一情绪；
  - 主色、辅助色与强调色的关系；
  - 与真实皮肤照片共存时的综合色彩表现；
  - 需要避免的医院、药品、医美、器械或儿童化联想。
- 在主题色决策完成前，不应默认继续沿用鼠尾草绿生成视觉草案。
- 状态：待专题探索。

### I-008 — 主题色情绪层级候选

- 当前产品建议不是在“清新、温暖、活泼”之间平均折中，而是建立主次：
  1. “温暖、被接住”作为品牌核心情绪；
  2. “清新、有生命力”作为大面积空间和阅读氛围；
  3. “活泼、有趣”集中出现在贴纸、盖章、页面收藏和轻动效中。
- 选择该层级的原因：
  - 产品最重要的差异不是单次测肤技术，而是长期记录时不评价、不制造焦虑；
  - 纯清新路线容易落入常见护肤或健康产品的绿色系模板；
  - 纯活泼路线会削弱真实照片、隐私和长期观察的可信度；
  - 以温暖为核心，可以连接真实皮肤照片与手账容器，再用局部趣味降低记录负担。
- 初步色彩含义：
  - 不默认把鼠尾草绿继续设为主色；
  - 大面积背景可保留温暖、低刺激的纸张感中性色；
  - 功能主色需要避开医院蓝、药品绿和炎症红的直接联想；
  - 食物、睡眠、情绪等贴纸可以拥有受控的多色体系，不要求所有插画服从单一主色。
- 状态：仅为产品经理建议，待用户确认情绪层级后再提出具体色板。

## 四、分歧与处理

### C-001 — 生活因素关联是长期附加价值，还是核心价值

- 初始观点：趋势追踪作为第一核心承诺，生活因素关联作为积累数据后的长期回报。
- 用户意见：不能舍弃生活因素关联；只做趋势追踪会与大量现有产品同质化。
- 最终处理：确认“趋势 + 生活关联”为一体化核心价值。两者出现时间可以不同，但产品定位和数据闭环必须从第一天同时建立。

### C-002 — 现有视觉草案的皮肤指数与产品价值观冲突

- 现有草案：主页使用“肌肤指数 74/100”“状态良好”和环形分数作为主要反馈。
- 用户意见：评分会让用户感到被评价，痤疮加重时容易放大羞耻、挫败和焦虑，违背长期陪伴产品的初衷。
- 最终处理：
  - 放弃面向用户的皮肤指数和评级设计；
  - 旧稿只继续作为配色、植物感、留白和总体品牌氛围参考；
  - 后续首页、分析页和趋势页改用中性观察、历史对比、记录完整度和陪伴性反馈。
- 实施状态：本轮只完成产品决策，尚未修改现有前端草案和相关后端字段。

### C-003 — 三项能力是互斥路线，还是同一产品的不同层级

- 初始观点：把“证据型档案、温柔陪伴者、对话式 Agent”作为三条整体产品路线进行选择。
- 用户意见：
  - 证据型档案是实现陪伴与 Agent 的必要途径；
  - 温柔陪伴者是产品整体定位；
  - 对话式 Agent 是面向消费者的重要呈现方式。
- 最终处理：不再三选一，改用“能力底座—产品定位—交互呈现”三层模型，并明确结构化界面与对话式 Agent 各自适合的任务。

### C-004 — 对话式 Agent 是否应作为独立产品入口

- 先前设想：将“陪伴”或“问答”设置为一级导航，由 Skin Agent 承担解释和情绪支持。
- 用户意见：
  - 独立多轮问答会导致 LLM 成本不可控；
  - 开放输入会吸引大量脱离产品定位的问题；
  - 产品应由 AI 赋能，但不能成为通用大模型的套壳聊天入口；
  - AI 应在固定产品 Function 中根据不同用户数据静默生成个性化输出。
- 最终处理：
  - 移除独立问答/陪伴入口；
  - 将 AI 能力嵌入今天、历程、周报和关联提示等既有流程；
  - 将结构化、事件触发、可缓存的固定 Function 作为 AI 产品架构；
  - 后端既有通用聊天能力不再自动等同于 App 端必须暴露的 MVP 功能。
- 实施状态：本轮只完成产品决策，尚未调整 `project_background.md` 中的 MVP 描述、移动端导航或后端聊天接口。

### C-005 — 避免用户怀疑照片被上传，是否可以替代明确告知

- 用户担忧：只要照片发生变化，用户就有合理理由怀疑隐私照片被上传给 AI；这会破坏产品信任。
- 已确认共识：产品不得对真实皮肤照片进行生成式修改，详见 D-018。
- 必须区分：
  - “是否修改照片”是图像真实性问题；
  - “是否向第三方或云端发送照片”是个人信息处理与数据流问题；
  - 即使照片从未被修改，只要曾发送给第三方模型，也必须真实说明，不能依靠界面没有变化来弱化或隐藏该事实。
- 当前建议：
  - 优先在端侧或自有受控服务中完成图像特征提取；
  - 只把去身份化后的结构化特征交给 LLM 生成观察文案，不把原始脸部照片交给通用 LLM；
  - 如果技术上必须把照片发送给外部视觉模型，应采用单独告知、单独同意、最短留存、可撤回与可删除机制，并明确服务方、目的和处理范围；
  - 若暂时无法满足上述信任条件，MVP 宁可只保存照片、不提供 AI 图像识别，也不应作出无法兑现的隐私承诺。
- 状态：图像真实性红线已确认；具体识别架构与隐私告知方式待后续技术及合规验证。

### C-006 — 隐私授权应当保持低存在感，还是突出分项控制

- 用户意见：
  - 希望授权体验与市面上大部分 App 的常见表现一致；
  - 如果设计得过于特殊或突出，反而会引起用户额外关注；
  - 倾向使用常见的长隐私文档与勾选同意方式，不希望在主流程中铺开过多权限细节。
- 产品与合规风险：
  - 真实脸部照片及皮肤状态分析涉及高度敏感的数据处理；
  - 通过冗长、难读或强制滚动的文档降低用户理解，并不能形成稳固的知情同意；
  - 把非必要分析授权与 App 基础记录功能绑定，会与“用户拒绝 AI 后仍可使用基础功能”的原则冲突。
- 当前折中建议：
  - 视觉形式沿用常见、克制的系统弹窗和标准设置列表，不使用警报式设计；
  - 首次启动只处理通用隐私规则，完整政策通过链接提供；
  - 第一次真正启用照片分析时，再用一屏简短说明完成单独授权，明确目的、处理位置或服务方、留存与退出方式；
  - 主页面只展示简洁的权限摘要，不平铺技术细节；详细分项控制放在二级管理页；
  - 允许“暂不启用分析”，且不影响拍照、贴纸记录和历史回看。
- 状态：分歧已记录，折中方案待用户确认。

### C-007 — 未形成的数据能力应隐藏，还是提前让用户知道

- 初始建议：数据不足时不展示照片对照和生活线索入口，避免锁图标、灰态卡片和“解锁”话术带来付费墙感。
- 用户意见：
  - 如果完全不出现，用户无法知道坚持记录后还会获得哪些长期能力；
  - 用户可能在新价值形成前就卸载产品；
  - 这会削弱产品对长期记录的解释和留存动力。
- 共同目标：
  - 不能把正常数据积累伪装成付费解锁；
  - 也不能把照片对照和生活线索等长期回报完全隐藏。
- 待确认方案：使用可点击的“未来会形成什么”预览，让用户提前理解长期价值；预览不加锁、不使用灰色禁用态、不倒计时，也不承诺一定产生某条洞察。
- 状态：分歧已确认，具体呈现方案待用户选择。

## 五、待决问题

2. 插画更偏纸质拼贴、邮票收藏，还是更轻盈的数字贴纸？

7. 日记完成后的即时奖励采用动效、连续天数、页面收藏，还是更克制的反馈？
